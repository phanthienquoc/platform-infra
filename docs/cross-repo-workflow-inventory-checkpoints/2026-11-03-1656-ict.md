## Platform Infra workflow roles

- `.github/workflows/gitops-image-promotion.yml`: receives app-owned repository dispatches; verifies source repository/workflow/event/branch/SHA and required publisher jobs; validates GHCR digests; scopes manifest changes; opens and validates an exact-head GitOps PR; squash-merges only after required validation; dispatches the existing reconciliation workflow.
- `.github/workflows/reconcile-vps.yml`: **sole production apply authority**. Owns shared GHCR pull preflight/credentials, GitOps drift/apply, workload rollout and health gates.
- `.github/workflows/inspect-vps.yml`: read-only K3s/VPS inspection; writes the diagnostic snapshot only.
- `.github/workflows/recover-stale-ops.yml`: recovery controller; may dispatch the existing inspection or reconciliation workflow when source-run freshness/conclusion gates require it. It does not run kubectl/SSH/Compose itself.
- `.github/workflows/reconcile-schedule-watchdog.yml`: read-only schedule freshness, conclusion and queue observer. Push smoke is diagnostic only and never counts as native schedule delivery.
- `.github/workflows/validate-manifests.yml` and `.github/workflows/validate-github-actions.yml`: validation-only; retain as required checks.
- `.github/workflows/mirror-locally-uncensored.yml`: purposeful scheduled mirror job; keep enabled and fail visibly until its destination-only token is configured.
- Backup, runner bootstrap, metrics, security, manual and release workflows remain purposeful; do not delete based only on a duplicate-looking name.
